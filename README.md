# ubiquex

`ubx`: infrastructure change management via a proposal ledger.

Every infrastructure change is a typed, hashed, signed proposal in an append-only
ledger. Current infrastructure = fold(applied proposals). Talks to Terraform
providers directly (tfplugin v5/v6), no Terraform, no state files.

**Status:** pre-alpha. Releases (`v0.1.0` on) publish via GitHub Releases.

## Where this sits

The coordinating repo for the whole org. Depends on
[ubx-provider-dynamic](https://github.com/Ubiquex/ubx-provider-dynamic)
(launched as a subprocess for every provider not hand-written directly
against a real HashiCorp binary) and the three shared SDK runtimes
([ubx-sdk-go](https://github.com/Ubiquex/ubx-sdk-go),
[ubx-sdk-typescript](https://github.com/Ubiquex/ubx-sdk-typescript),
[ubx-sdk-python](https://github.com/Ubiquex/ubx-sdk-python)), each
mounted as a real git submodule under `sdk/`, compiled directly into
the `ubx` binary.

Everything else in the org depends on this repo: all six
`ubx-sdk-<provider>` bindings repos and all six
`ubx-schema-<provider>` snapshot repos are generated by, or resolved
through, `ubx sdk gen`/`provider.AcquireSchema` here.
[ubiquex-docs](https://github.com/Ubiquex/ubiquex-docs) (the
user-facing documentation corpus) and
[ubiquex-internals](https://github.com/Ubiquex/ubiquex-internals) (the
architecture and design site) both document this repo's own real,
current behavior, never the other way around.

## What it contains

- `core/`: IR, ledger, canonical hashing
- `provider/`: tfplugin v5/v6 client
- `cli/`: the `ubx` binary's own commands
- `cmd/`: the real `ubx` binary entry point
- `sdk/`: the multi-language SDK monorepo (codegen, conformance, and
  the three runtime submodules, TypeScript/Go/Python)
- `blueprint/`: reusable, parameterized proposal templates (Ubxfile
  parsing, per-language codegen)
- `writeback/`: surgical `.tf`/diagram/markdown edits (`ubx writeback`)
- `github/`: acceptance derivation from a real, reviewed pull request
- `audit/`: per-cloud drift/genesis attribution backends
- `conformance/`: per-type registry and adversarial test harness
- `diagram/`, `mdrender/`: the D2 diagram and markdown authoring mediums
- `docs/`: architecture, schema constitution, plan, session prompts

See `docs/source-tree.md` for the full, real package-by-package layout.

## How to use it

```
make build    # ./ubx, prints `ubx version` immediately after
make install  # go install, then verifies PATH actually resolves it
```

No published release binary yet (pre-alpha), build from source. `ubx
version` after either target confirms the binary you just built is the
one on your `PATH`, not a stale prior build (UBI-63's own real
incident: a stale binary gave a founder an identical, pre-fix-looking
result during a real AWS re-test).

## How it's maintained

`CLAUDE.md` and `STATE.md` in this repo are the session-open protocol
every working session on this codebase follows. `STATE.md` holds only
current, in-flight state, rewritten, not appended, as the last act of
every session; `HISTORY.md` is the narrative archive. Design decisions
live in `docs/` and are never silently contradicted by an
implementation change.
